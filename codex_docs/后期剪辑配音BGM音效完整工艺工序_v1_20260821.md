## 0. 文档目的

本文定义从“镜头视频已经通过内容准入”到“可发布 MP4 与平台发行包”的完整后期生产链。它覆盖：

1. 素材接收与精确 SHA 绑定；
2. 画面剪辑、对白剪辑、动作场剪辑与接缝设计；
3. 配音、对白对齐、角色声线绑定与可懂度验证；
4. BGM 选曲/生成、版权溯源、分段编排与对白闪避；
5. 环境声、拟音、动作音效、转场音效与静默治理；
6. 字幕编译、时间绑定、烧录与 OCR 验证；
7. 分轨混音、响度、峰值、连续声床与母版绑定；
8. 画面锁定、音频锁定、总装、成片 QA、发行包与发行回执；
9. 各执行 Agent 的权限、输入、输出、失败分流和并行规则；
10. 当前实现、已知分歧、禁止旁路和后续收敛项。

本文不改变 canonical 剧本，不替代镜头生成阶段的 Q1/Q2 内容准入，也不授权上传、发布、删除或超预算付费动作。发布仍由已授权平台配置和发行门控制。

## 1. 权威层级与术语

### 1.1 权威层级

从高到低：

1. Roger 明确指令与带授权号的治理决议；
2. canonical 剧本、canonical manifest、角色/声音/场景/道具资产注册表；
3. `configs/GATE_REGISTRY_v3_20260716.json` 中已注册 gate_id；
4. 本文的工艺合同；
5. AgentCut project、编辑计划、cue sheet、mix manifest、render manifest；
6. QA 报告和执行回执；
7. 临时探针、harness、经验阈值和审美建议。

低层不得反向改写高层。未注册的诊断指标不得以 P0/P1 硬门身份停线或触发付费重做。

### 1.2 核心术语

- **canonical**：经确认且可作为生产唯一事实来源的正式版本。后期不得自行改台词、角色归属、事件顺序或结局。
- **admitted source**：已经通过适用注册门、可进入总装的镜头素材。
- **picture lock**：画面镜头、入出点、顺序、转场与总时长冻结；之后不得无回执改画面。
- **audio lock**：对白、BGM、环境、拟音、SFX 的源文件、时间、增益、处理和最终混音 SHA 冻结。
- **published mix**：包含已准入镜头同源原生对白、环境、拟音、SFX 及合法补层的唯一发行母版，也是后续返修、替换和总装唯一允许继承的已批准音轨。这里禁止的是未准入 candidate、旧版本或其他 remote task 的音频回流；不得误读为删除当前准入镜头的原生音轨。
- **cue**：一条可审计的声音事件，含来源、时间、用途、增益、淡入淡出与权利信息。
- **stem**：dialogue、foley、ambience、music、sfx 等可独立监听与重混的分轨导出。
- **Q1/Q2**：Q1 为关键帧/静态内容准入，Q2 为动态视频内容准入；技术解码 PASS 不等于内容准入。
- **zero-cost remedy**：裁切、换取材帧、调色、重排、遮罩、重新对齐、重混等不产生新付费生成任务的修复。

### 1.3 实施状态标记

- `IMPLEMENTED`：仓库有通用脚本、合同或注册门，可复用执行。
- `PARTIAL`：有能力或单集脚本，但没有统一通用入口/合同/回归测试。
- `MANUAL`：需要人类原速观看、聆听、平台操作或边界仲裁。
- `SPEC_REQUIRED`：本文定义了必须具备的合同，但当前仓库尚未完整实现。

## 3. 执行 Agent 的完整定义

### 3.1 Postproduction Supervisor（后期总监 Agent）

职责：

- 读取 canonical、镜头准入清单、work_queue 和后期依赖图；
- 建立每集唯一 `postproduction_manifest`；
- 拆分画面、对白、音乐、音效、字幕、混音、总装和 QA 工位；
- 保证每条工位绑定真实输入 SHA、输出 SHA、进程或 task_id；
- 决定可并行项、合流点与下一安全动作；
- 拒绝伪活跃、重复 POST、候选音频回流和未注册门停线。

不得：改 canonical；自行批准平台账号；绕过付费事务；把诊断报告写成准入证据。

输入：episode manifest、admitted source manifest、registered gate snapshot。
输出：postproduction manifest、lane 状态、合流决议、blocker manifest。

### 3.2 Picture Editor / AgentCut Agent（画面剪辑 Agent）

职责：

- 把准入镜头编译为 frame-exact timeline；
- 每个切点写明封闭词表中的剪辑动机；
- 保持 scene_id、light_key、axis_line、eyeline 连续；
- 对动作生成单元建立 sub-cut plan，而不是把 4–15 秒生成单元直接当成片镜头；
- 设计 J-cut、L-cut、动作桥、反应停留和场景预声；
- 只用真实素材解决 coverage，不用变速、插帧、循环、定格填时长。

主要实现：

- `tools/generate_agentcut_timeline.py`
- `tools/build_agentcut_from_admitted_storyboard_sources.py`
- `tools/edit_plan_integrity_gate.py`
- `tools/cut_motivation_gate.py`
- `tools/fight_cut_plan_gate.py`
- `tools/transition_smoothness_gate.py`
- `tools/frame_exact_materialization_gate.py`

### 3.3 Dialogue & Voice Agent（对白/配音 Agent）

职责：

- 从 canonical 精确提取 dia_id、说话人、正文、情绪和时间窗；
- 先查 canonical voice registry，不得临时选“像一点”的声音；
- 生成或选择语音时保留 provider/model/version/voice asset/task/credit/SHA；
- 执行文本一致性、ASR、角色声线绑定、可懂度、削波与时长适配；
- 语音必须跟随台词语义和动作呼吸，不得以字幕替代缺失对白。

Seedance 2 说话镜头属于原生多模态成品，Dialogue Agent 只验证并保留该镜头自带对白；画面、对白音频必须绑定相同 source_id、相同 multimodal task_id 和同一媒体源。不得删除原声后使用 TTS、旧候选音轨或另一视频任务的声音重配。外置配音只适用于明确没有同步说话口型的旁白/画外音，或具备 `NO_NATIVE_DIALOGUE_WITH_EVIDENCE` 的非说话素材路线。

主要实现：

- `tools/generate_agentcut_character_voice_references.py`
- `tools/agentcut_character_voice_reference_guard.py`
- `tools/dialogue_audio_release_gate.py`
- `tools/speaker_identity_voice_release_gate.py`
- `tools/rebuild_agentcut_dialogue_windows_from_asr.py`
- `tools/apply_agentcut_speech_safe_trim_plan.py`

### 3.4 Music Supervisor / BGM Agent（音乐 Agent）

职责：

- 为整集建立音乐叙事弧，不按镜头机械铺满；
- 决定生成型剧集 BGM 或有依据的库乐 fallback；
- 绑定 generation task/receipt/credits/source SHA 或 library music_id/权利/相似度报告；
- 建立 cue sheet、情绪功能、入点、出点、淡变和对白 duck；
- 输出 `Audio.BGM` 轨和 solo stem。

主要实现：`tools/bgm_authenticity_gate.py`。
状态：`PARTIAL`。真实性、来源和可听性门已实现；统一的跨模型音乐 provider adapter、完整 rights ledger 和通用 cue 编译器尚未收敛。

### 3.5 Sound Designer / SFX Agent（环境声、拟音、音效 Agent）

职责：

- 建立 ambience、foley、sfx 三种独立语义层；
- ambience 维持空间与时间连续；foley 支撑人物接触和材质；sfx 强调叙事事件；
- 每条音效必须有画面因果或明确主观声设计意图；
- 禁止用大音量撞击音掩盖动作不成立，禁止用同一 whoosh 填满所有切点；
- 输出 cue sheet、素材权利、源 SHA、轨道时间和 solo stem。

状态：`PARTIAL`。仓库存在分层约束和若干单集音效/环境修复脚本，但尚无统一 `sfx_cue_contract`、通用生成/素材库 adapter 和独立注册 gate。当前不得把零散脚本冒充完整自动化 SFX 工位。

### 3.6 Subtitle Agent（字幕 Agent）

职责：

- 使用 canonical 纯台词，剥离“角色名：”前缀；
- 由源音频 ASR 时间窗变换到成片时间轴；
- 保证 dia_id 顺序、文本、覆盖、唯一性和安全区；
- 输出烧录轨，而非只附外挂字幕；
- 对最终像素执行 OCR/抽样视觉验证。

主要实现：

- `tools/add_agentcut_subtitle_track.py`
- `tools/audit_agentcut_caption_source_binding.py`
- `tools/verify_burned_subtitles.py`
- `tools/final_video_ocr_audit.py`

### 3.7 Re-recording Mixer / Mastering Agent（混音母版 Agent）

职责：

- 按 dialogue / foley / ambience / music / sfx 分轨混音；
- 确保对白优先、BGM duck、空间声床连续、无数字静音洞和危险响度跳变；
- 输出 stems、published mix、响度/峰值/时长报告、音频指纹与 SHA；
- 返修时继承 published mix 及其中已固定的准入原生音频 lineage；不得继承未准入 candidate、旧版本或其他 remote task 的音频。替换可见口型镜头时，新画面必须携带其同一 task 的原生对白并重新形成 published mix。

主要实现：

- `tools/render_agentcut_audio_master.py`
- `tools/audio_postproduction_contract.py`
- `tools/sound_cue_contract.py`
- `tools/audio_source_binding_gate.py`
- `tools/final_audio_provenance_gate.py`
- `tools/audit_final_native_source_audio_binding.py`

### 3.8 Final QA Agent（成片 QA Agent）

职责：技术解码、逐镜观看、身份/动作/时代复核、对白可懂度、字幕、音频连续性、重复画面、节奏事件、品牌和发行包检查。必须区分机器证据、人工证据和诊断信息。

不得：以自身 waiver 通过问题；以平均分掩盖最弱项；以 ffprobe PASS 代替完整观看。

### 3.9 Packaging & Release Agent（封装与发行 Agent）

职责：统一分段规格、总装 MP4、烧录字幕、添加 Nalu Motion 片尾、绑定最终 SHA，执行平台 preflight，并持久化 YouTube/抖音成功回执。

不得：绕过登录/验证码；猜账号或文案；把上传成功当发布成功；把抖音“审核中”写成已发布。

## 4. 后期主数据合同

### 4.1 `postproduction_manifest`

每集唯一，最少字段：

```json
{
  "schema": "qingshan.postproduction_manifest.v1",
  "episode": "E40",
  "canonical_script": {"path": "...", "sha256": "..."},
  "admitted_sources": [{"shot_id": "R01", "path": "...", "sha256": "...", "q2_gate": "..."}],
  "picture_project": {"path": "...", "sha256": "...", "status": "ROUGH_CUT"},
  "dialogue_contract": "...",
  "bgm_cue_sheet": "...",
  "sfx_cue_sheet": "...",
  "subtitle_contract": "...",
  "mix_manifest": "...",
  "render_manifest": "...",
  "blocker_manifest": "..."
}
```

### 4.2 `edit_timeline_contract`

每个画面 clip 必须有：segment_id、source path、source SHA、source in/out、timeline start/duration、fps、frame range、shot_id、scene_id、room_id、zone_id、cut_reason、cut_reason_note、light_key、axis_line、eyeline、dialogue_id 或 picture-only 声明。

动作场 sub-cut 额外需要：generated_duration、sub-cut duration、phase（windup/burst/result）、动作事件、反应/结果、禁止 retime 声明。

### 4.3 `dialogue_audio_manifest`

每行至少：dia_id、canonical text、speaker/entity_id、voice asset id、voice reference SHA、provider/model/version、task_id（如付费）、transaction receipt、raw source SHA、processed source SHA、ASR 文本与相似度、起止时间、情绪、处理链、最终轨道位置。

### 4.4 `bgm_cue_sheet`

每条至少：music_id 或 generation task_id、source_type、source SHA、rights evidence、cue_id、timeline in/out、source in/out、narrative function、entry/exit motivation、gain、dialogue duck、fade/crossfade、是否允许跨场景。

### 4.5 `sfx_cue_sheet`

每条至少：cue_id、layer（AMB/FOLEY/SFX）、event_id、visual cause、subjective intent（若无画面因果）、source path/SHA、license/生成回执、timeline in/out、gain、pan、fade、scene_id、room_id、material、是否可复用。

### 4.6 `mix_manifest`

至少包含：所有 stem 路径和 SHA、所有源 cue 的 SHA、处理链、自动化参数、采样率/声道、目标响度、true peak、最终 published mix SHA、audio fingerprint、与最终视频 SHA 的绑定。

### 4.7 `render_manifest`

至少包含：picture lock SHA、published mix SHA/fingerprint、字幕合同 SHA、片尾资产 SHA、输出编码、帧数、时长、最终 MP4 SHA、所有注册门报告路径及 SHA。

## 5. PP-00 素材接收与预检

### 输入

- Q2 `ADMITTED_FOR_ASSEMBLY` 的镜头；
- canonical 剧本和对白合同；
- 角色/声音/场景/道具 registry；
- 已授权的 BGM/SFX 素材库或生成 provider；
- 品牌片尾和平台配置。

### 工序

1. 仅收录精确 SHA 与 Q2 准入报告一致的镜头。
2. ffprobe 记录视频/音频流、分辨率、fps、时长、time_base、start_time、采样率、声道。
3. 标记每镜音频策略：`USE_NATIVE`、`REPLACE_DIALOGUE_KEEP_BED`、`MUTE_AND_REBUILD`、`PUBLISHED_MIX_ONLY`。
4. 识别源音频中的对白、环境和生成噪声；未经审听不得默认复用。
5. 建立 immutable source inventory；后续所有计划只引用 inventory id 和 SHA。
6. 如镜头缺 Q2 准入，只隔离该镜，不阻塞独立镜头和声音预制。

### 输出

- admitted source inventory；
- media probe report；
- audio strategy map；
- postproduction manifest 初版。

### 禁止旁路

- 直接把工作目录里“最新文件”拖入时间线；
- 用文件名版本号代替 SHA；
- 把技术可解码当内容准入；
- 返修画面时自动带回候选视频自带音频。

## 6. PP-10 画面编辑计划

### 6.1 剧情和事件映射

把 canonical 拆为 event ledger：事件、证据、动作、反应、不可逆变化、对白、场景和情绪转折。每个成片镜头必须服务至少一个事件或明确视觉意图。

### 6.2 每个切点必须有理由

允许的主要剪辑动机：说话人变化、新信息、新空间、动作落点、反应情绪变化、首次建立、真实景别变化、可阐明的构图意图。禁止“为了 ASL、节奏指标、填时长、做快切”作为理由。

### 6.3 连续性

同场景接缝检查：scene_id、light_key、axis_line、eyeline、动作方向、道具状态、伤口/服装、空间地图继承。无连续性字段的切点不可进入正式计划。

### 6.4 原生时序

必须保留 native fps，不允许：setpts 变速、minterpolate、stream_loop、loop、tpad 定格复制、用静帧延长、用重复帧补时长。coverage 缺口只能用新素材、已有合法覆盖或删改剪辑解决。

### 6.5 打斗与高速动作

生成单元不等于成片镜头。4–15 秒视频应按真实动作事件切成 4–6 个 sub-cut，每段有动作/反应/结果和剪辑动机。打斗基线由已注册 `ACTION-SHOT-DESIGN-AND-STATE-HANDOFF` 下的 `fight_cut_plan_gate.py` 负责，并由 `episode_stage_gate_runner.py` 的 edit phase 执行；禁止用 slow motion 或 speed ramp 假造冲击力。单段 12 秒生成视频直接作为一个成片镜头必须 BLOCK。

### 6.6 声画接缝

当前注册合同：

- 对话 J/L cut 占比至少 0.6；
- 同帧声画硬切占比不高于 0.2；
- J-cut 声音提前 300–600 ms；
- L-cut 声音延续 200–400 ms；
- 对白等功率交叉淡变 10–20 ms；
- 场景 ambience/BGM 预声 500–1000 ms；
- ambience 等功率交叉淡变 40–80 ms；
- 动作切点可偏移 2–4 帧；
- 台词后反应停留 150–300 ms。

这些是已注册合同参数。对不适用的镜头应在计划中说明，而不是悄悄删除字段。

### 输出与门

- frame-exact edit plan；
- transition plan；
- fight cut plan（适用时）；
- `EDIT-PLAN-NATIVE-CADENCE`；
- `EDIT-CUT-MOTIVATION`；
- `EDIT-VIEWING-CONSISTENCY`；
- `TRANSITION-SMOOTHNESS`。

## 7. PP-20 粗剪、精剪与 Picture Lock

### 粗剪

1. 先按事件和对白建立完整可读版本；
2. 保留镜头源音频供参考，但不将其默认作为发布音频；
3. 检查开场钩子、事件间隔、信息重复、动作方向和结尾悬念；
4. 对问题按“删、缩、换已有覆盖、调整顺序、局部画面修复、补拍/重生成”排序，先零成本处理。

### 精剪

1. 锁定逐帧入出点；
2. 落实所有 cut reason；
3. 对白不得切断音节、词尾、吞咽或关键呼吸；
4. 反应镜头必须带来新情绪/信息，不能作为填充；
5. 相邻和非相邻重复画面检查；
6. 画面亮度、轴线、眼线、运动方向和空间地图连续。

### Picture Lock 条件

- 所有 source SHA 可回溯；
- frame-exact materialization PASS；
- 无 retime/freeze/loop；
- 每个切点有合法动机；
- 每个事件有可见表达；
- 逐镜观看证据完整；
- 问题清单为空或有具名外部裁决。

Picture lock 后任何画面更改必须产生新 project SHA、重跑字幕时间、混音长度和最终 QA。

## 8. VO-10 配音完整工艺

### 8.1 台词编译

1. 从 canonical 提取 dia_id，不从字幕、旧成片或临时文案反推；
2. 锁定正文、说话人、语境、事件刺激、情绪残留、动作和目标时长；
3. 不为适应 TTS 擅自改字；必要的剧本等价调整必须回到 canonical 层留痕。

### 8.2 声音资产查询

优先级：canonical voice asset → 经授权同角色备选 → 新建经授权 voice asset。不得跳过资产库直接“凭感觉选声线”。每个声音引用绑定 remote_asset_id、来源、授权、示例 SHA 和角色实体 ID。

### 8.3 表演设计

每句至少定义：

- 情绪起点与终点；
- 对谁说、为什么现在说；
- 语速、停顿、重音和呼吸；
- 是否伴随运动、受伤、压低声线或距离变化；
- 与上一句的残余状态。

禁止全句同速、统一播音腔、无事件动机的“高级感”、每句末尾机械降调。

### 8.4 生成与事务

对 Seedance 2 原生说话镜头，本节不授权重新生成配音。画面 source_id、对白音频 source_id 和多模态 task 必须相同；口型不合格时回视频生成链修复该镜，不能靠后配音掩盖。

- 本地零成本 TTS：记录模型、commit/revision、license、voice id、参数和 SHA；
- 付费 TTS：POST 前持久化事务，成功后立即绑定 task_id，收割后权威分类扣费/退款；
- 超时或未知状态不得重提；
- 原任务终态、费用分类、失败归因和实质提示/参数变更完成后，方可在上限内重试。

以上 TTS 规则仅适用于无同步口型的旁白/画外音或已证明不存在原生对白的来源。对 Seedance 多模态说话镜头使用 TTS 属于硬失败。

### 8.5 语音 QA

逐句执行：

1. 文件可解码、非空、时长合理；
2. ASR 与 canonical 精确或达到注册合同；
3. 角色 voice asset 正确；
4. 可懂度、口齿、断词、数字/专名、情绪和呼吸人工/机器检查；
5. 无削波、爆音、底噪突变和尾部截断；
6. speaking frame、canonical face 和 canonical voice 的证据绑定（适用时）。

### 8.6 时长适配

先改剪辑窗、停顿和安全 trim；不得用明显变速损坏人声。音频不足时不可用静音填对白区；音频过长时不得截断语义。字幕不能替代缺失对白。

禁止把另一候选视频的原生对白音轨贴到当前说话画面，即使角色、文本和时长相同也不允许；这种做法无法保证音素、嘴形和微动作逐帧同步。

### 准入门

- `EXACT-DIALOGUE-AUDIO-MANIFEST-COVERAGE`
- `SOURCE-VIDEO-NATIVE-DIALOGUE-ASR`
- `DIALOGUE_AUDIO_AUDIBILITY`（final package blocker 中的必需证据）
- `SPEAKER_IDENTITY_AND_VOICE_BINDING`

## 9. MU-10 BGM 完整工艺

Seedance 2 是多模态视频生成：准入镜头默认保留其自带对白、环境、拟音和动作音效。BGM 是独立背景音乐层，只在确有叙事渲染需要的时间段加入，不得全片默认铺设，也不得替代或覆盖原生音效。

### 9.1 音乐功能设计

先写整集音乐弧，再选曲。每条 cue 的功能只能是可说明的叙事目的，例如：威胁潜伏、信息揭示、人物立场变化、动作爆发、余波、结尾悬念。BGM 不得单独承担本应由表演、剪辑、环境或音效完成的情绪。

### 9.2 来源策略

当前合同只允许：

- `GENERATED_EPISODE_BGM`：新生成剧集音乐；
- `LIBRARY_FALLBACK`：有具名失败原因和跨集相似度 PASS 的库乐回退。

生成音乐必须保存 task_id、生成回执、source SHA 和精确 credit evidence。库乐必须保存 music_id、授权证据、fallback reason 和跨集相似度报告。

音频 profile 必须显式选择：

- `NATIVE_MULTIMODAL_SELECTIVE_BGM`：Seedance 原生多模态底轨，BGM 可选；一旦加入，必须同时存在 `Audio.BGM`、`bgm_contract`、`usage_mode=SELECTIVE_NARRATIVE_CUES` 和逐 cue 的时间窗/叙事功能；
- `NATIVE_MULTIMODAL_NO_EXTERNAL_BGM`：完全不加外部 BGM；出现 `Audio.BGM` 或 BGM 合同即失败；
- `LAYERED_POST_WITH_BGM`：对白、环境、拟音、SFX 等被独立重建的特殊后期路线，BGM 为显式必需层。

当前新编译的标准 Seedance 项目默认使用第一种，而不是“整集强制 BGM”。

### 9.3 Cue 编排

1. 标记入点、出点、源入出点和叙事功能；
2. 避免每场从头开始同一首；
3. 对白区执行 -6 至 -10 dB duck（现有 BGM 合同）；
4. 场景变换用 500–1000 ms 预声与 40–80 ms 等功率交叉淡变；
5. 关键台词、动作落点或静默设计可让音乐退出；
6. 不用音乐掩盖对白、音效、错误接缝或无戏画面。

### 9.4 BGM QA

- `Audio.BGM` 轨真实存在且有 clips；
- 所有源文件存在、非空、SHA 一致；
- solo stem 可听：现有门要求 mean 不低于 -35 dB、peak 不低于 -18 dB；
- 生成型来源回执/积分一致，库乐回退理由和相似度证据齐全；
- mixed output 存在；
- 逐集人工听审检查重复、抢词、情绪误导和不自然起落。

注册门：`BGM-SOURCE-PRIORITY-AUTHENTICITY`。

## 10. FX-10 环境声、拟音与音效完整工艺

### 10.1 五层声音结构

1. **Dialogue**：叙事信息与人物表演；
2. **Foley**：脚步、衣料、手接触、道具、身体运动；
3. **Ambience**：室内底、风、雨、人群、虫鸣、远处活动，维持空间连续；
4. **Music**：整集情绪与结构；
5. **SFX**：冲击、法术、武器、转场、主观耳鸣等强调层。

### 10.2 Cue 设计顺序

1. 先建每场 ambience 底；
2. 再补对叙事可见接触有必要的 foley；
3. 再补动作结果和超自然事件 SFX；
4. 最后才考虑转场 whoosh、低频 hit 等风格化音效；
5. 与 BGM 联听，避免所有层同时争抢同一瞬间。

### 10.3 因果合同

每条 cue 必须回答：声音来自什么、在空间何处、为什么此刻听见、与画面事件的时间差、是否为角色主观声。无因果且无主观设计说明的 cue 不准进入正式 mix。

### 10.4 动作/打斗声设计

- 起势可用衣料/脚步，不用每个动作都 whoosh；
- 接触点用材质匹配的 impact；
- 结果用物体、身体、空间反射表达；
- 一次重击应有前后动态差，不靠全程高响度；
- 不用 SFX 掩盖动作轨迹错误或接触未发生。

### 10.5 连续声床

相邻片段必须保持 room tone/ambience 连续。注册门 `FINAL-AUDIO-BED-CONTINUITY` 当前要求：数字静音定义约 -90 dB、无动机静默最长 1 秒、相邻 RMS 跳变不超过 12 dB。静默若为叙事设计，必须在 cue sheet 中具名。

### 10.6 当前实现缺口

现已增加统一 `tools/sound_cue_contract.py`，并在不新增 gate_id 的前提下接入已注册 `FINAL-AUDIO-BED-CONTINUITY`。它支持两种模式：Seedance 原生多模态 `NATIVE_EMBEDDED`，以及外置环境/拟音/SFX 的 `LAYERED_CUES`。正式母版入口会再次执行该合同，builder 漏接时不能生成 published mix。

仍需后续补齐：

- solo stem 可听性和最终混入验证；
- 跨集音效重复诊断；
- provider-neutral 音效生成 adapter。

这些缺口不得被临时 harness 擅自升级成新硬门；应先走 gate registry 治理。

## 11. SUB-10 字幕完整工艺

1. 字幕正文来自 canonical expected text；
2. 剥离角色名前缀和脚本标记；
3. 通过源音频 ASR 时间窗映射到 timeline，而不是按镜头平均分配；
4. dia_id 顺序、覆盖、唯一性必须与 expectedDialogueIds 完全一致；
5. 默认样式由 `add_agentcut_subtitle_track.py` 提供，字体必须为真实存在的 CJK 字体；
6. 字幕必须烧录，最终不能只交外挂轨；
7. 最终像素执行 burn-in 验证和 OCR audit；
8. 道具中文字与对白字幕分属不同合成层，不能互相替代。

当前通用默认样式包含字号 42、白字黑描边、底部居中、安全边距和每行约 15 字换行；这是 renderer 默认值，不应被误写为所有平台永恒审美硬门。平台安全区变化时应通过配置版本化。

## 12. MIX-10 混音与母版工艺

### 12.1 轨道组织

建议固定总线：

```text
DX  dialogue
FL  foley
AM  ambience
MU  music
FX  sound effects
MX  published mix
```

每个总线可 solo 导出并绑定 SHA。不得只保存最终 AAC 而丢失源轨和处理合同。

### 12.2 信号流程

1. 清理与剪辑源；
2. clip gain；
3. 必要的 EQ/降噪/去爆音；
4. 对白动态控制；
5. 轨道自动化与空间；
6. BGM duck；
7. ambience/foley/sfx 平衡；
8. bus limiter；
9. integrated loudness 与 true peak 校验；
10. 输出 stems 和 published mix。

### 12.3 当前已存在参数

- transition contract：目标 -16 LUFS，容差 ±1 LU；
- AgentCut master：loudnorm `I=-16:TP=-1.5:LRA=11`；
- 多个发行项目使用 AAC 192k、48 kHz、stereo；
- 部分单句 TTS QA 使用 -20 至 -14 LUFS 或更窄范围、true peak ≤ -1 dBFS。这些是源语音/单集局部标准，不应冒充最终整集母版标准。

### 12.4 已发现的实现分歧（必须修复或显式选择）

`agent_factory/AGENTS.md` 的最终封装规定 AAC 48 kHz。2026-08-21 修复前，`tools/render_agentcut_audio_master.py` 内部输出 44.1 kHz；现已统一为 48 kHz，并在 profile、renderer 输出探测和回归测试三处 fail closed：

1. 通用 master renderer 固定为 48 kHz；
2. `output.audioSampleRate` 与 `masterAudioPolicy.sampleRateHz` 必须同时声明 48000；
3. 输出后由 ffprobe 复核实际 sample rate；
4. `tools/tests/test_render_agentcut_audio_master.py` 生成真实母版并断言 48000 Hz。

### 12.5 Published Mix 绑定

一旦 audio lock：

- 保存 published mix 文件 SHA 和音频 fingerprint；
- 所有 repair plan 的 audio track 必须声明 `source_type=published_mix`；
- 每个替换段必须声明候选音频已丢弃；
- 未处理区间的 fingerprint 必须与已批准 mix 一致；
- 任何新处理区间必须在 provenance manifest 中声明。

注册门：`AUDIO-SOURCE-PUBLISHED-MIX-BINDING`、`FINAL-AUDIO-PROVENANCE`、`FINAL-AUDIO-BED-CONTINUITY`。

## 13. PKG-10 总装与编码

### 13.1 分段归一化

平台/API/片头/正片/片尾来源不同，必须逐段归一化后再 concat：

- 720×1280；
- fps 以当前集 canonical manifest 的显式值为唯一权威；manifest 未声明时 30 fps 仅作历史兼容 fallback，禁止无声明地把 24/23.976 fps 插帧成 30 fps；
- PTS-STARTPTS / ASETPTS-STARTPTS；
- yuv420p；
- AAC 48 kHz；
- 每段从 0 时间戳开始。

最终 concat 再 re-encode 一次。禁止直接拼接带可变帧率、非零 start_time、不同采样率或像素格式的 MP4。

### 13.2 字幕与品牌

- 烧录中文字幕覆盖全部 canonical dia_id；
- Nalu Motion 片尾启用、位于时间线末端且至少 2.5 秒；
- render manifest 必须绑定最终 MP4 SHA；
- 最终文件为平台兼容 MP4，而非仅交 MKV 中间母版。

### 13.3 编码建议与权威边界

仓库通用路径主要使用 H.264/libx264、yuv420p、AAC 192k、48 kHz 和 `+faststart`。CRF/preset 在历史单集脚本中不一致，因此本文不把某个 CRF 写成新增硬门；正式生产应由一个版本化 release profile 收敛，且平台 profile 与 render manifest 完整记录。

## 14. QA-10 完整后期 QA 矩阵

### 14.1 技术层

- MP4 可完整解码；
- 视频/音频流存在；
- 分辨率、fps、像素格式、采样率、声道、时长和起始时间符合 profile；
- 无 VFR/时间戳漂移；
- 总帧数和 timeline frame-exact；
- 无周期重复、非动机长定格、插帧或 retime 痕迹。

### 14.2 画面剪辑层

- 每镜和每切点有事件/动机；
- 无重复填充、空插镜、同源无信息重复；
- 场景、轴线、眼线、动作方向、光线和状态连续；
- 打斗有可切多回合、爆发/蓄势结构和真实冲击点；
- 逐镜观看记录，不以解码报告代替。

### 14.3 对白层

- canonical 台词完整、顺序正确、说话人正确；
- 可听、可懂、无截词、无错字、无字幕代替对白；
- 角色 face/voice 绑定证据齐全；
- 对白窗与画面说话状态合理；
- 声桥和交叉淡变无咔哒、无双声和无故静音。

### 14.4 BGM 层

- 来源和权利/生成/积分证据；
- cue 叙事功能真实；
- 不抢对白、不铺满、不重复滥用；
- duck 与 crossfade 合同通过；
- solo stem 可听，最终 mix 中实际存在。

### 14.5 环境/拟音/SFX 层

- 每场空间声床存在且连续；
- 关键接触有对应材质声音；
- SFX 与画面事件同步且因果合理；
- 无 whoosh/hit 模板化滥用；
- 无数字静音洞、RMS 突跳和跨场景错误 ambience。

### 14.6 字幕/OCR 层

- dia_id 100% 覆盖、顺序一致、无重复；
- 文本与 canonical 一致，无说话人前缀；
- timing 与源音频绑定；
- 最终像素可见、无遮挡、不过安全区；
- OCR 不出现伪字/残留旧字幕；
- 道具真字与对白字幕均满足各自合同。

### 14.7 混音/母版层

- stems 和 published mix SHA 完整；
- -16 LUFS 目标及注册容差；
- true peak 符合发布 profile；
- 对白在手机扬声器和普通耳机均清晰；
- 完整 1× 正常声、静音画面、只听声音三遍检查；
- 最终视频音频 fingerprint 与 published mix 绑定。

### 14.8 发行包层

以下四项采用 `evidence:` 前缀，均为 `FINAL-PACKAGE-BLOCKERS` 的内部证据键，不是独立 gate_id：

必须具备：

- `evidence:DIALOGUE_AUDIO_AUDIBILITY`；
- `evidence:SPEAKER_IDENTITY_AND_VOICE_BINDING`；
- `evidence:SUBTITLE_BURNIN`；
- `evidence:NALU_MOTION_OUTRO`；
- `AUDIENCE_SCORE_PRE_RELEASE` PASS；
- 所有 blocker resolved 或具名合法批准；
- 最终 MP4、manifest、QA 与 SHA 相互一致。

| 自我豁免 | `FINAL-CUT-NO-SELF-WAIVER` | 执行 Agent 不得自批问题 |

| 人工视听 | `AGENT-WATCH-LISTEN` | 完整观看/聆听清单 |
| 观众模拟 | `AUDIENCE-SCORE-PRE-RELEASE` | FULL/MUTED/SOUND 三遍与钩子 |
| 品牌发行 | `RELEASE-BRANDING-CONTRACT` | 字幕、片尾、最终 SHA |
| 最终 blocker | `FINAL-PACKAGE-BLOCKERS` | 所有发行阻塞清零 |
| 签核 | `RELEASE-SIGNOFF-INTEGRITY` | 签核来源和 Roger override 可追溯 |

临时脚本不得发明相似名称后冒充上表的注册 gate_id。

## 16. 失败分流与返修策略

### 16.1 归因

- `SOURCE_DEFECT`：准入素材本身错误；回镜头生产链。
- `EDIT_DEFECT`：入出点、顺序、重复、连续性或切点错误；在 AgentCut 修。
- `DIALOGUE_DEFECT`：台词、声线、ASR、表演或时长错误；重做单句/局部。
- `MUSIC_DEFECT`：来源、cue、抢词或叙事错误；换 cue/重混，必要时生成。
- `SFX_DEFECT`：缺失、因果、同步、材质或模板化；改单 cue。
- `SUBTITLE_DEFECT`：正文、绑定、样式或烧录错误；重编字幕。
- `MIX_DEFECT`：响度、峰值、声床或平衡；重混，不重生画面。
- `PACKAGE_DEFECT`：时间戳、编码、拼接、片尾或 SHA；重新总装。
- `TEMPLATE_DEFECT`：同模板多单元同因失败；模板层修一次，再处理受影响组。

### 16.2 零成本优先

重生成前依序尝试：裁切、换帧、换已有覆盖、重排、局部遮罩/合成、重新字幕、重新对齐、重混、重封装。P0 身份/关键实体/动作因果错误不得以 `ADMIT_BEST_EFFORT` 凑合。

### 16.3 返修影响面

- 只改声音源：重跑对白/混音/音频 provenance/总装/最终 QA；
- 只改字幕：重跑字幕绑定、烧录、OCR、总装/最终 QA；
- 改画面时长或顺序：字幕、所有 cue、mix、总装和最终 QA 全部失效；
- 只重封装且内容帧/音频样本不变：仍需新最终 SHA、技术 QA 和品牌/发行门绑定。

## 17. 并行调度规则

可以并行：

- 已锁台词的逐句 TTS；
- BGM 候选/来源核验；
- ambience/foley/SFX cue 预制；
- 已准入镜头的粗剪；
- 字幕文本编译；
- 已 picture-lock 前缀的声音设计。

必须等待：

- 字幕最终时间绑定等待 picture lock 或可追踪时间映射；
- 最终 mix 等待 picture lock；
- final render 等待 audio lock、字幕锁和品牌资产；
- 发行等待完整注册门、最终 SHA 和平台 preflight。

远端声音/音乐任务等待期间，编辑、字幕预编译、cue sheet、资产清单和已准入前缀总装不得停。

## 20. 当前实现审计结论

### 已实现并可复用

- frame-exact 编辑计划和禁止 retime；
- cut motivation、观看连续性、fight sub-cut、transition contract；
- canonical 对白/音频 manifest 覆盖与 ASR 检查；
- canonical face/voice 发布绑定证据；
- 字幕源时间绑定、烧录与 OCR；
- BGM 来源优先级、付费证据、library fallback 和 solo stem 可听性；
- 显式音频 profile、Seedance 原生多模态底轨与选择性 BGM 的互斥/共存合同；
- SFX/foley/ambience 的原生嵌入或外置 cue 来源、SHA、权利、空间与因果合同；
- AgentCut published mix 48 kHz 输出与实测回归；
- Seedance 原生说话画面与原生对白同源绑定：外部 TTS、旧候选对白复用、跨 candidate 音轨替换均在 builder 和母版入口 fail closed；
- published mix 文件 SHA、audio fingerprint 和返修绑定；
- 音床连续、最终音频 provenance、品牌/片尾/最终 SHA；
- 最终 blocker、观看证据、观众模拟和发行 preflight。
- 打斗剪辑门、编辑计划、剪辑动机、观看连续性、帧落地、音频绑定和转场门已由统一 `episode_stage_gate_runner.py` 执行；全部逐集 AgentCut release builder 均在渲染边界 fail closed 调用该统一入口。

### 局部实现或存在分叉

1. SFX/foley/ambience 的通用 cue validator 已实现，但素材库/生成 provider adapter、solo stem 混入验证和跨集重复诊断仍未统一；
2. 历史 AgentCut project 缺新 `audio_profile_id`，重跑时必须迁移，不能静默 grandfather；
3. 历史脚本的响度、CRF、分辨率和 fps 参数不完全一致；需要单一 versioned release profile；
4. BGM 已有真实性门和选择性 cue 合同，但通用生成 provider adapter 和跨模型能力未完全统一；
5. 配音存在通用守门与多个单集执行器，但“事务先行的 provider-neutral TTS submitter”仍需收敛；
6. 部分人工视听证据仍是必要步骤，尚未全部转为客观自动判据。

### 禁止的错误结论

- “有 `bgm_authenticity_gate.py`”不等于 BGM 创作全自动；
- “有若干 SFX 脚本”不等于 SFX 通用流水线完成；
- “ffprobe/ASR PASS”不等于观感和表演 PASS；
- “最终有声音”不等于来源、权利和 published mix 绑定 PASS；
- “有字幕轨”不等于最终像素已烧录；
- “有 MP4”不等于可发行成片。

## 21. 外部 AI 审核清单

外部审核者应逐项回答：

1. 是否只有 Q2 admitted source 能进入正式 edit timeline？
2. 每个 source/clip/cue/mix/render 是否都绑定精确 SHA？
3. 是否存在未通过统一门的第二条编辑、配音、BGM、SFX、字幕或 POST 入口？
4. 所有切点是否有真实动机，而非指标语言？
5. 动作生成单元是否被合法 sub-cut，而非一段一镜或变速？
6. canonical 台词、说话人和 voice asset 是否逐 dia_id 绑定？
7. 付费 TTS/BGM 是否事务先行、task_id 立即绑定、费用终态明确？
8. BGM 是否有真实来源、权利/积分、cue 功能和可听 stem？
9. ambience/foley/SFX 是否逐 cue 有因果、来源、SHA 和权利？
10. 是否存在 BGM 替代环境声、SFX 替代动作成立、字幕替代对白的情况？
11. published mix 是否唯一；其是否保留当前准入镜头的同源原生音频，并明确排除未准入 candidate、旧版本和其他 task 的音频？
12. 44.1/48 kHz 分歧是否已解决并有测试？
13. 字幕是否从源音频映射，最终像素 OCR 是否通过？
14. 最终 MP4 是否统一时间戳、fps、像素格式和 AAC 48 kHz？
15. 所有 blocker 是否引用已注册 gate_id？
16. 是否完整 1× 观看、静音看、只听声音，而非只跑机器指标？
17. 最终 MP4 SHA 是否与 render manifest、QA、平台上传对象完全一致？
18. YouTube 和抖音是否分别有真实发布成功回执，而非上传/审核中状态？
