## 1b. The D-10 pre-step — how a new episode gets its own preproduction inputs

`build_nalu_preproduction.py` (S2) hard-fails on a `scene_id` its GSM does not map, and
`bootstrap_identity_cards.py` (S3) requires both `preproduction/<EP>/asset_requirements.json`
and `preproduction/<EP>/prompts/`. E01 authored all three by hand. For every other episode the
orchestrator generates them with the two episode-agnostic builders, in this order, before S2 —
and again (cached, one call per process) at the head of S3:

| # | tool | argv | why this order |
|---|---|---|---|
| 1 | `runtime/tools/extend_global_space_map.py` | `--episode --contract --manifest --base-gsm <prev or E01> --out preproduction/<EP>/global_space_map.json --asset-dir …/space_map_assets --reports-dir …/reports --engine-root $ENGINE_ROOT --python $VENV` (plus `--place-spec` if `preproduction/<EP>/new_location_place_spec.json` exists) | must precede S2. **Without** `--asset-requirements` on this pass, because those do not exist yet |
| 2 | `runtime/tools/build_episode_asset_requirements.py` | `--episode --contract --narrative --manifest --directing --prior-library runtime/asset_library.json --out-dir preproduction/<EP>/ --gsm <the map from step 1>` **plus `--overlay preproduction/<EP>/asset_requirements_overlay.json` when that file exists** (`overlay.json` is accepted as an alias) | needs the GSM for the `所属空间图 … / 房间 …` line of every location prompt |
| 3 | `extend_global_space_map.py` again | same as 1, now **with** `--asset-requirements` | picks up a new location's authored `key_fixed_elements`. Free: for the same `--episode` the tool is byte-identical-idempotent |

**Base map.** The base is the **previous episode's** locked `global_space_map.json` when it
exists (it already carries every earlier episode's places), else E01's.

**E01 changes nothing.** When both `global_space_map.json` and `asset_requirements.json`
already exist the pre-step runs *nothing at all* and records
`action: REUSED_EXISTING`.

**Fail-closed on authoring gaps.** `build_episode_asset_requirements.py` exits **3** when an
`AUTHORING_REQUIRED_*` sentinel landed in the output — a field no script layer carries and no
overlay supplied. The files are still written so the gaps are inspectable, but a sentinel must
never be baked into a paid prompt, so S2/S3 stop with stage status **`AUTHORING_REQUIRED`**,
list the gaps, and name the overlay to author:

```
preproduction/<EP>/asset_requirements_overlay.json   schema nalu.episode_asset_requirement_overlay.v1
  character priority / apparent age / sex · wardrobe state prose · per-location label +
  spatial_topology + key_fixed_elements · directing-script-only props · voice timbre briefs ·
  the accent profile · the SFX table
```
Author it, then `run --episode <EP> --from S2`. The gaps are listed in
`preproduction/<EP>/asset_requirements_build_report.json`.

**Auto-siting is a warning, not a pass.** If the extension report lists `auto_sited`, the new
place's geometry is gate-clean but *where it sits relative to the village* was chosen by the
tool. The stage records `AUTO_SITED_REQUIRES_SPATIAL_REVIEW` as a warning — a human confirms it
or authors `preproduction/<EP>/new_location_place_spec.json`.

**Never resolve the interpreter path.** `.qingshan-venv/bin/python` is a symlink to
`python3.12`; `Path(...).resolve()` on it silently leaves the virtualenv and PIL disappears, so
the place-map render dies with `ModuleNotFoundError`. The orchestrator passes `$VENV`
unresolved and so must you.

## 2. Money safety — the two locks and the guard

A paid step runs only when **both** are true:

1. `--paid` was passed on the command line, **and**
2. `$RUNTIME_ROOT/qingshan.json` → `generation.paid_requests_enabled` is `true`
   (today: **false**).

`--dry-run` overrides both. When paid steps are disabled the orchestrator runs the engine
tool's own precheck/dry twin (`--precheck-only` for all three submitters, `qingshan
video-preflight` for video) and prints the exact paid argv with resolved absolute paths, also
saved to `pipeline_logs/<EP>/<run_id>_planned_paid_commands.json`.

Before **every** paid step:

```bash
$VENV $RUNTIME_ROOT/runtime/tools/nalu_budget_ledger.py \
  --check --episode <EP> --planned-credits <N> --cap 8000
```

A non-zero exit is a `HARD_STOP`: the run stops, nothing is submitted, exit code 3. Standing
order `SUPERVISOR_ORDERS.json` seq=3 condition 2, `BUDGET_CAP_8000_PER_EPISODE`. The guard is
fully offline unless `--refresh-balance` is passed.

Child-process environment (from `runtime/engine_patches/e09_nalu_entity_registry_extension.diff`):

| variable | value |
|---|---|
| `QINGSHAN_VOICE_REGISTRY` | `runtime/voice_registry.json` |
| `QINGSHAN_ENTITY_REGISTRY` | `runtime/nalu_entity_registry.json` (additive, fail-closed; registering the nalu cast **subjects** it to the multimodal binding guard, it cannot exempt it) |
| `QINGSHAN_AGENTCUT_VOICE_POLICY` | `runtime/agentcut_character_voice_reference_policy_nalu.json` |
| `QINGSHAN_CHARACTER_REGISTRY` | set only if the file exists — **see D-1** |
| `QINGSHAN_DURABLE_SUBMITTER_CONTEXT` | `1`, **only for a genuinely paid step** (`giggle_api_client.py:117-130` refuses generation POSTs without it) |
| `GIGGLE_API_KEY` | **stripped** from every non-paid child, so a free step physically cannot reach a paid endpoint |
| `BACKLOT_PIPELINE_TOOLS_DIR` | `$ENGINE_ROOT/tools` — **S6 only**, exported for `submit_giggle_video_manifest_v2.py` and `poll_giggle_submit_report.py`. See §2c |
| `PYTHONPATH` | prefixed with `$ENGINE_ROOT` for every child |

### 2b. The rights basis (D-3 residual, now closed)

`tools/initial_asset_library.py gate` demands `rights.status == PASS` with a **named** basis. A
rights basis is a legal declaration by the line owner; no measurer and no reviewer can observe
one, so this pipeline neither derives nor invents it. Roger made the declaration on
**2026-09-09** in `SUPERVISOR_ORDERS.json` seq=3
(`ROGER-20260909-NALU-E01-E10-PRODUCTION-AUTHORIZED`), conditions **3**
`CHARACTER_SOURCE_FOLDER` (Roger supplies the character source folder) and **7**
`RIGHTS_OFFLINE` (adaptation authorisation handled offline by Roger; the engine does not verify
it). The orchestrator passes it verbatim:

```
--rights-basis "SUPERVISOR_ORDERS seq=3 c3/c7 — Roger 提供角色图并线下处理肖像与改编授权（2026-09-09）"
```

to **`bootstrap_identity_cards.py`** and to **`identity_qa_lock.py lock`**, and records it in
`runtime/pipeline_state/<EP>.json` under `rights_basis` with
`declaration_type: LINE_OWNER_DECLARATION_NOT_A_REVIEWER_OBSERVATION`, the order id, the
conditions and the authority path. `status` and every `CHECKPOINT.md` reprint it.

It covers **identity reference plates only**. Order seq=3 explicitly does *not* authorise
publication, so **R-2** (adaptation / commercial rights) and **R-5** (voice copyright evidence)
stay open on Roger's side as *release* blockers. `--accept-source-qa` is still never passed:
`qa.status` comes from the real VLM plate review plus the real insightface cosine, never from an
operator declaration.

### 2c. D-11 — paid authorisation immediately before every paid submit

Every submit needs a real `authorization_ref` and `provider_post_allowed: true`, and the image
submitter's `validate_submission_authority` (which `--precheck-only` **skips**) additionally
needs **exactly one** `GIGGLE-REROLL-COST-GUARD` report bound to the submitted manifest's exact
byte SHA. Immediately before each paid submit the orchestrator runs:

```bash
$VENV $RUNTIME_ROOT/runtime/tools/materialize_paid_authorization.py \
  --episode <EP> --order-seq 3 \
  --plan|--manifest <the file about to be submitted> \
  --ledger $RUNTIME_ROOT/runtime/budget/ledger.json \
  --report $RUNTIME_ROOT/runtime/reports/<EP>_paid_authorization_<s3|s5|s6>.json
```

and then submits the **`…_PAID_AUTHORIZED.json` copy it writes**, never the original — which
stays on disk un-authorised as evidence of what was compiled.

| stage | input | submitted file |
|---|---|---|
| S3 | `identity/character_asset_plan.json` | `character_asset_plan_PAID_AUTHORIZED.json` |
| S5 | `<EP>_KEYFRAME_IMAGE_MANIFEST_V1.json` | `…_V1_PAID_AUTHORIZED.json` |
| S6 | `<EP>_VIDEO_TRANSACTION_MANIFEST_V1.json` | `…_V1_PAID_AUTHORIZED.json` |

* **Dry runs never execute it** — the exact command is printed and recorded in
  `<run_id>_planned_paid_commands.json`. It is offline and costs no credits, but
  `nalu_budget_ledger.py --check` **appends to the real ledger on every run**.
* **Re-run it after any edit** to the plan/manifest: the guard report binds the byte SHA.
* `provider_post_allowed: true` in a file is only **one** lock. `--paid` and `qingshan.json`
  `generation.paid_requests_enabled` remain independently required (today: `false`).
* Refusals exit **5** and write nothing but a refusal report (`ORDER_SEQ_3_DOES_NOT_EXIST`,
  `MODEL_FORBIDDEN_BY_ORDER_CONDITION_1`, `PLANNED_CREDITS_EXCEED_CAP`,
  `NALU_BUDGET_LEDGER_CHECK_NOT_PASS`, …). Exit **6** means the files were written but the
  submitter's own validator still refuses — read `self_verification.reason`.

### 2d. S6 and the video submitter's tools dir

`submit_giggle_video_manifest_v2.authoritative_pipeline_tools_dir()` looks for
`<project-root>/tools/production_video_submission_gate.py` and raises *"Production video gate is
unavailable"* **before any manifest validation at all** when it is absent. Two consequences:

1. S6 exports `BACKLOT_PIPELINE_TOOLS_DIR=$ENGINE_ROOT/tools` for the submitter, its
   `video-preflight` twin and the poll tool.
2. `--project-root` is **`$ENGINE_ROOT`** (the engine), *not* the runtime as earlier
   drafts of this runbook said. `production_video_submission_gate.evaluate_manifest(..., root)`
   resolves each task's *relative* `prompt_file`
   (`workflow/nalu/<EP>/preproduction/video_prompts/<UNIT>.txt`) against that same root, so a
   runtime root could only ever report `CURRENT_PROMPT_FILE_MISSING`, even after stage 4.4
   compiles the prompts. `build_nalu_preproduction.py`'s own stage-5/5b invocations already use
   the engine root; S6 now matches them.

Verified blocking reason for E01 today:

| | `--project-root` | `BACKLOT_PIPELINE_TOOLS_DIR` | blocking reason |
|---|---|---|---|
| before | `$RUNTIME_ROOT` | unset | `Production video gate is unavailable; restore tools/production_video_submission_gate.py …` |
| after | `$ENGINE_ROOT` | `$ENGINE_ROOT/tools` | `Authoritative BacklotOS production gate failed: CURRENT_PROMPT_FILE_MISSING` |

compiled `workflow/nalu/<EP>/preproduction/video_prompts/` because the anchor plan is

records the reason in `stages.S6.details.video_preflight_precheck.blocking_reason`. Seeing

child.

`generate_agentcut_character_voice_references.update_registry` is deliberately **not** used —
it indexes a qingshan-only id table and `KeyError`s on nalu ids. S4 writes the registry rows
itself, and every value it writes is observed (asset id/url from the provider receipt, SHA and
duration from the file on disk).

## 3. Commands

### Dry run (free stages for real, paid commands printed only)
```bash
$VENV $PIPE run --episode E01 --dry-run
```

### One episode, paid
```bash
export GIGGLE_API_KEY=…                              # only for paid/harvest steps
# and flip qingshan.json generation.paid_requests_enabled to true
$VENV $PIPE run --episode E01 --paid
```

### Resume / partial
```bash
$VENV $PIPE run --episode E01 --from S5 --until S6 --paid
$VENV $PIPE run --episode E01 --force --from S2      # re-run a stage that already PASSed
```

### Status
```bash
$VENV $PIPE status --episode E01
$VENV $PIPE status --episode E01 --json              # the whole state file
```

### Start the loop
```bash
$VENV $PIPE loop --start E01 --end E10 --paid --poll-seconds 60
```
The loop runs each episode's S1→S8 in order, then **always** writes
`deliverables/<EP>/CHECKPOINT.md` and blocks, polling
`runtime/pipeline_state/approvals/<EP>.APPROVED.json`. There is no `--yes`, no
`--auto-approve`, and no timeout that self-approves. A **failed** episode also gets a
checkpoint and also blocks — a human always looks before the next episode starts.

### Approve (unblocks the loop)
```bash
$VENV $PIPE approve --episode E01 --note "watched it, ship E02"
```
`approve` refuses if no checkpoint exists. It records the checkpoint SHA256 and the final
video SHA256 alongside the timestamp.

### Stop safely
* **Between episodes** — just don't run `approve`. The loop waits indefinitely; nothing is in
  flight.
* **During a free stage** — `Ctrl-C`. Every stage writes its state before and after, so the
  next run resumes from the last non-PASS stage.
* **During a paid submit** — `Ctrl-C` is safe *for the ledger* but not instantaneous: the
  submitter writes `state: INTENT_RECORDED` with `retry_guard:
  DO_NOT_RESUBMIT_UNTIL_LEDGER_RECONCILED` **before** the POST. After any interrupted paid
  step, before doing anything else:
  ```bash
  $VENV $RUNTIME_ROOT/runtime/tools/nalu_budget_ledger.py \
    --episode <EP> --refresh-balance --strict-balance
  ls $ENGINE_ROOT/workflow/tasks/giggle_video_submit_transactions/<EP>/
  ```
  Any transaction not in `VERIFIED_ZERO_RETRYABLE` will make the next run raise rather than
  re-POST. **Never delete a transaction file to "unstick" it** — that is how you pay twice.
* **Revoke an approval** — delete `runtime/pipeline_state/approvals/<EP>.APPROVED.json`.

### 3b. Resuming after an interruption mid-stage

Every stage writes its state before and after itself, so `run` always restarts from the first
stage that is not `PASS`/`SKIPPED_ALREADY_PASS`. What you must do first depends on *where* it
stopped.

| where it stopped | is money at risk? | do this |
|---|---|---|
| a free stage (S1, S2, S7, S8) or a QA sub-stage | no | `run --episode <EP> --from <STAGE>`. All of them are pure compilers or measurers and are safe to re-run |
| the D-10 pre-step | no | re-run; `extend_global_space_map.py` is byte-identical-idempotent for the same episode and `build_episode_asset_requirements.py` is a pure compiler |
| `materialize_paid_authorization.py` (D-11) | no POST, but it **appends to the ledger** | just re-run it — it replaces its own guard report and never duplicates the registered entry. Check `runtime/budget/ledger.json` for the extra `--check` rows it appended |
| **during a paid submit (S3, S4, S5, S6)** | **yes** | see below — never re-run blindly |
| the harvest / poll step | no (no generation POST) | re-run. `poll_giggle_submit_report.py` skips what is already downloaded; `harvest_giggle_image_batch.py` has no dry mode but issues no POST |

**After an interrupted paid submit — the API died, the process was killed, the network dropped:**

```bash
# 1. reconcile the ledger against the provider FIRST
$VENV $RUNTIME_ROOT/runtime/tools/nalu_budget_ledger.py \
  --episode <EP> --refresh-balance --strict-balance

# 2. read every durable transaction for this episode
ls $ENGINE_ROOT/workflow/tasks/giggle_submit_transactions/<EP>/          # images + plan
ls $ENGINE_ROOT/workflow/tasks/giggle_video_submit_transactions/<EP>/    # video

# 3. only then
$VENV $PIPE run --episode <EP> --from S6 --paid
```

* The submitters write `state: INTENT_RECORDED` with
  `retry_guard: DO_NOT_RESUBMIT_UNTIL_LEDGER_RECONCILED` **before** the POST, under a per-task
  `flock`. A task already `SUBMITTED_TASK_ID_BOUND` with the same submission fingerprint is
  **recovered, not re-POSTed** — so a plain re-run costs nothing for work already paid for.
* A lost HTTP response becomes `RESPONSE_LOST_PENDING_LEDGER_RECONCILIATION`. The next run
  **raises rather than re-POSTing**. Reconcile step 1 first.
* **Never delete a transaction file to "unstick" it.** That is exactly how you pay twice.
* If the manifest was edited during the outage, re-run `materialize_paid_authorization.py`
  before resuming: the cost-guard report binds the manifest's byte SHA and an edited manifest
  invalidates it.
* S3/S4/S5 additionally have SHA-keyed reuse authorities
  (`runtime/asset_library.json`, `runtime/voice_registry.json`) — a subject already `LOCKED`
  with a matching artifact SHA, or a voice already `LOCKED_PRODUCTION_READY` with a matching
  wav, is skipped without any submission at all.

**If the interruption hit a machine review** (the run had exited `4`): nothing is in flight. Re-run
`vlm_review_protocol.py submit` if the answers file was written but the submit never completed,
then `run --episode <EP> --from <STAGE>`. A submitted review is automatically discarded and
re-requested if any media it looked at has changed byte-for-byte since.

## 4b. QA — machine review, and the sub-stages that run it

Line-owner policy: **the line runs continuously with a human check only after each finished
episode.** Every per-asset QA is therefore a **machine review** — deterministic measurers where
the engine has them, plus a **VLM structured review** performed by a Claude reviewer process
that actually looks at the media and answers a closed questionnaire. Every record carries
`reviewer: "claude-code-nalu-vlm"` and the reviewer's real observations. **No PASS is written
without a review having happened, and a review that finds a defect produces FAIL/REJECT plus a
reroll request.**

### The reviewer contract

```bash
export VLM=$RUNTIME_ROOT/runtime/tools/vlm_review_protocol.py

$VENV $VLM request --kind identity|keyframe|start_frame|post_gen_plot|video_q2 --episode E01 \
    [--items '["E01-S01-01"]'] [--out <path>]
$VENV $VLM example-answers --request <request>          # ALL VALUES null — not a review
$VENV $VLM submit  --request <request> --answers <answers.json>
$VENV $VLM questionnaire --kind keyframe                # print the closed question set
```

A request under `runtime/reviews/<EP>/` carries, per item: every media path with its exact
sha256, the **authoritative expectations** read out of the authored layers (appearance /
entry_state / cast / props / space / wardrobe / dialogue / scene_state / negative prompts), a
closed vocabulary, and the questionnaire. `submit` refuses unless every item is answered with
enumerated values, every item has a free-text observation of ≥20 characters, a defect list is
present, the reviewer is exactly `claude-code-nalu-vlm`, and the answers are bound to the
request's sha256. `UNCERTAIN` is never a pass.

| kind | items | questions | feeds |
|---|---|---|---|
| `identity` | one per plate subject (plan groups ∪ source-matched subjects) | 13 — appearance, age, sex, all card deliverables present, single subject/no clone, cross-view identity, wardrobe, palette+lighting, forbidden influences, no burned text, framing+aspect, face usable, photographic-not-illustrated | `asset_library.qa.checks` (D-3) |
| `keyframe` | one per planned keyframe | 14 — entry-state-only, cast exactly as declared, screen slots/depth planes, props, space anchors, camera+axis, lighting/palette/time, wardrobe, closed-set anachronism, no burned text, per-character identity, action-role topology, no freeze/reset/replay, no P0 defect | `VLM_STRUCTURED_STATE_QA_V1` + the SCENE/PERIOD evidence rows (D-4) |
| `start_frame` | one per video unit | 6 — entry-state-only, camera start framing match, space match, empty establishing frame, required characters visible, required props visible; plus observed character/prop/space-anchor lists | `qingshan.start_frame_semantic_evidence.v1` (D-5) |
| `post_gen_plot` | one per video unit, over the original mp4 plus an ffmpeg 2-fps contact sheet | exactly the 5 basic-plot checks the scope gate allows: episode_scene_correspondence, principal_character_presence, major_event_presence, major_dialogue_presence, chronological_unit_order | the post-generation QA record (D-6) |
| `video_q2` | one per video unit, over the **original-resolution** 720×1280 mp4 plus the 5 frames `video_q2_builder.py prepare` extracted from it | 12 — cast exactly as declared, per-character identity stable, space anchors, camera axis, lighting/palette/time, declared entry-state→completion-state handoff completes, props present + end state, wardrobe, closed-set anachronism, no burned text, no extra/replayed beat, no P0/P1 defect. **Every one is inside `post_generation_qa_scope_gate.py`'s allowed scope — none of its 16 forbidden gesture / microexpression / choreography / trajectory / optical-flow / motion-energy checks is asked.** A P2 defect must carry `shot_index` (1-based inside the unit's `editorial_shot_ids`) and `at_seconds` | the Q2 `VIDEO_ASSEMBLY` admission (D-7) |

## 4c. The review loop — how a `REVIEW_REQUIRED` run is answered

The line runs continuously with a human check only after a finished episode, so every per-asset
QA is a **machine review**: deterministic measurers plus a structured VLM review by the Claude
reviewer process, `claude-code-nalu-vlm`. Five sub-stages can ask for one — S3.qa (`identity`),
S5.q1 (`keyframe`), S5.sfe (`start_frame`), S6.qa (`post_gen_plot`), S6.q2 (`video_q2`).

```
run --episode E01            →  stage writes runtime/reviews/E01/<id>_request.json
                                state.review_required is set, exit code 4
$VENV $VLM example-answers --request <request>   →  an ALL-NULL template (never a review)
   … the reviewer OPENS every media path in the request and answers every question …
$VENV $VLM submit --request <request> --answers <answers.json>
run --episode E01 --from S6  →  the stage picks the submitted review up and continues
```

* `status --episode <EP>` prints the outstanding request and these exact commands;
  `qa-status --episode <EP>` prints every route's readiness as JSON.
* `submit` refuses unless every item is answered with an enumerated value, every item carries a
  free-text observation of ≥20 characters, a defect list is present (`[]` when none), the
  reviewer id is exactly `claude-code-nalu-vlm`, and the answers are bound to the request's
  sha256. **`UNCERTAIN` is never a pass**, and a FAIL or UNCERTAIN answer without a defect entry
  is a validation failure.
* A submitted review is **bound to the bytes it looked at**. If any media's sha256 has changed
  since — a rerolled keyframe, a re-downloaded clip — the review is ignored and a fresh one is
  requested. A review can never be inherited by a different image.
* On `submit`, the per-kind materialiser runs automatically and writes the engine-format
  evidence (`identity_qa_lock`, `keyframe_q1_builder`, `start_frame_evidence_writer`,
  `post_generation_qa_runner`, `video_q2_builder`). The orchestrator re-runs it anyway, so
  either order works.
* Exit codes: `0` ok · `2` a stage did not pass · `3` budget `HARD_STOP` · `4` machine review
  required. In a **dry run** the runner keeps going past a review-required or blocked stage so
  the whole plan prints, and still returns the worst code.

## 4d. What Roger sees at the checkpoint

S8 always writes `deliverables/<EP>/CHECKPOINT.md` — for a failed episode too — and then blocks
on `runtime/pipeline_state/approvals/<EP>.APPROVED.json`. There is no `--yes`, no
`--auto-approve`, and no timeout that self-approves. The checkpoint contains, in this order:

1. **Stage status table** — every stage, its status, and its blockers.
2. **What to watch** — when the cut exists: `deliverables/<EP>/<EP>_final_9x16.mp4` with its
   sha256, plus `<EP>_QA_REPORT.json`. When it does not: an explicit *"there is no cut to watch
   yet"*, the list of artifacts that *do* exist to review (preproduction report, 29-unit
   grouping plan, video transaction manifest, identity bootstrap report, the identity / keyframe
   / Q2 admission route statuses, the post-generation QA summary, the AgentCut admission, the
   loudness report, the voice payloads), and a pointer to the state file, where the first
   non-passing stage names its own `blockers` and `details.missing_input`.
3. **QA summary** — the interesting verdicts per stage (gate 10, character entity contract,
   engine report status, machine gate reports, keyframe entry-state gate, asset-library gate,
   post-generation QA scope, video-preflight, efficiency, submitter precheck).
4. **Rights basis on record** — the basis string, who declared it and when, that it is a
   line-owner declaration and not a reviewer observation, the order id and conditions, its
   scope, and explicitly what it does **not** cover (release).
5. **Credits vs cap** — the 8000 cap, recorded spend, planned spend this run per stage, the cost
   plan total, and the ledger path.
6. **Known defects / open decisions blocking release**, then the ones resolved since the last
   checkpoint with their residuals.
7. **Approval** — the one command that unblocks the loop.

```bash
$VENV $PIPE approve --episode E01 --note "watched it, ship E02"
```

`approve` refuses without a checkpoint, and records the checkpoint sha256 and the final video
sha256 alongside the timestamp. Revoke by deleting the flag file. **No platform upload is ever
performed by this pipeline.**
