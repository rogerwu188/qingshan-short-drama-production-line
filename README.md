# Mac 生产线局域网预同步工具

用于将指定生产目录从旧 Mac 拉取到新 Mac。使用系统自带 Bash、SSH、rsync 和图形对话框，不要求 Python，也不自动安装软件。

本分支/下载包仅含迁移工具，不是生产引擎，不能拿它替代完整生产仓库或旧机的未提交工作树。实际代码与运行数据由明确的私密迁移清单从旧机同步。

这只是文件预同步工具，不是完整生产迁移器：不会开启源机 SSH、启动生成/发行、安装后台任务、重建环境或转移生产执行权。生产仍可能写入，预同步结果不保证数据库一致性。

## 使用

1. 旧机主人开启“系统设置 → 通用 → 共享 → 远程登录”，只允许必要账户；不必向其他人提供聊天中的登录密码。
2. 旧机代理通过私密渠道交付 `source_config.env`、指定的主机公钥文件和生产交接文档。配置格式见 `source_config.example.env`。真实配置、设备身份和交接材料不上传公共 GitHub。
3. 在新 Mac 下载本工具。将私密配置和公钥放在同一私人目录；若配置不在工具目录，启动后会弹出文件选择框。
4. 双击 `Receive-on-new-Mac.command`，选择源地址、接收目录和可选依赖。系统若阻止打开，请核实下载来源后按系统提示允许该文件，不要全局关闭安全保护。
5. 在终端输入旧机登录密码。密码不会显示，也不会保存。公钥自动严格核验，不需手工输入 yes。
6. 先看预演，再确认实际预同步。只写所选位置内的 `Production-Migration-Receive/staging`，保留源绝对路径层级，但不写入新机系统用户根。

需要新机本地或直连磁盘至少 12 GiB 可用空间；网络共享目标被拒绝，以免把资料写回旧机。该下限不是对任何项目容量的保证，实际体积更大时应提前增加空间。断线或空间不足会记为失败，已接收文件保留。再次选择同一位置可增量恢复。

## 配置与信任

配置仅允许明确列出的 `KEY=value`，不支持 shell 表达式、source、eval、引号或行尾注释。`SOURCE_HOME` 是旧机用户目录，不带尾斜线。`ROOT_n_REL` 是其下精确的相对目录/文件，连续编号，最多 32 个；每项必须声明 `KIND=dir/file`、`OPTIONAL=0/1`。不要把整个主目录作为一项，也不要把全部聊天索引和应用凭据纳入。

旧机代理应读取旧机真实 ED25519 主机公钥并用系统 `ssh-keygen -l -E sha256 -f` 核实指纹，再将公钥和匹配指纹私密交付。指纹格式为 `SHA256:...`，公钥文件应是单行的 `ssh-ed25519` 公钥（不含注释）。工具不通过未验证的网络连接自动信任主机。

每次连接只使用本次私有 known_hosts，固定 ED25519 公钥，`StrictHostKeyChecking=yes`。所有后续查询及 rsync 都沿用相同验证，不读取/修改用户全局信任。地址变化仍必须匹配同一把公钥，硬件来源绑定也必须一致。不匹配时停止，不能关闭验证。

不需要将登录密码、API Key、云存储秘密或发布者私钥放入本配置。凭据另经受保护渠道按最小范围配置；不要放到公开仓库、报告或聊天。

## 安全和限制

- 不使用 `--delete` 或源文件删除；目标必须有本工具创建的标记，拒绝接管无关目录。
- 同一接收目录不能并发运行；来源硬件变化会被拒绝。
- 保留符号链接，不递归追踪外部链接。绝对链接及 `.git` worktree 路径需要新机代理核实，不能因文件传输成功就认定可运行。
- 排除可重建虚拟环境、缓存和常见秘密文件，包括 `.env`、`env`、`credentials`、`publisher_key.json`、`admin.token`、`*.pem`、`*.key`、`.ssh`、登录 token 等。排除规则不是自动脱敏证明；源清单必须人工/代理审查。
- 每根成功/失败写入私有日志。`RSYNC_OK` 只表示 rsync 返回成功，不是 SHA 校验、创作验收或迁移完成。
- 不自动清理旧机磁盘。只有最终迁移验收后另行批准清理。

## 最终切换必须另行完成

旧机安全停止新提交和相关写盘 → 记录在途任务、账本、授权、版本及未提交修改 → 最后增量同步 → SHA、数据库、环境和免费测试验证 → 双方明确唯一生产执行者 → 新机先恢复/对账已有任务，再经正规入口生产。联系不上旧机时不能推断已停机；不能双机重复付费或发行。

## 离线测试

在本目录运行 `bash receiver.sh --self-test`。测试使用临时合成配置和临时生成的测试公钥，不连接网络，不运行真实 rsync/SSH，不读生产资料。另可运行 `bash -n receiver.sh`。GUI 和真正的双机传输需要在实际迁移时验证；离线通过不能冒充实机迁移完成。
